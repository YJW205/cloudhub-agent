# Day 7 · 03 面试模拟题库

> 30 道高频题，按组分类。【必背】= 你答不出就露馅；【加分】= 答出显深度。
> 自测方法：盖住答案，口头答 1 分钟，再对照。全部过一遍约 2 小时。

## A 组 · LLM 基础

**1. 什么是大语言模型（LLM）？**【必背】
基于 Transformer 的深度神经网络，在海量文本上预训练，学会"根据上文预测下一个词"。本质是概率模型，所以可能编造（幻觉）。

**2. system prompt / user prompt 有什么区别？**【必背】
system 是给模型的"角色设定和规则"，user 是用户输入。我的项目用 system 约束"何时检索、何时算钱、不许编造"。

**3. temperature 参数影响什么？**【必背】
控制输出随机性。0 附近稳定保守（计算、分类用）；高值更发散有创意（写作用）。我的项目设 0.2，产品问答要确定性。

**4. 什么是 token？**【加分】
模型处理文本的最小单位，中文一个汉字约 1-2 个 token。计费按 token，上下文有长度限制。

**5. 什么是幻觉（hallucination）？怎么减少？**【必背】
模型生成看似合理但错误/不存在的内容。减少手段：RAG（给事实依据）、限制知识边界（"文档中未找到"）、低 temperature、工具调用（事实从工具来）。

## B 组 · LangChain 核心

**6. 什么是 LCEL？举个你的例子。**【必背】
LangChain Expression Language，用 `|` 连接组件成管道：`prompt | llm | parser`，支持 invoke/stream/batch。Day2 练习写过。

**7. 链（Chain）和 Agent 的区别？**【必背】
链是**固定顺序**（写死的流程）；Agent 是**模型自主决策**——根据情况决定下一步（调工具、回答），LangGraph 用循环实现。

**8. Runnable 是什么？**【加分】
一切可调用的组件（prompt/llm/parser/chain）都实现了 Runnable 接口（invoke/stream/batch），所以能自由组合。

## C 组 · Agent 与工具调用

**9. 什么是工具调用（function calling）？流程是什么？**【必背】
模型不真执行代码，而是输出"想调用哪个工具、参数是什么"（tool_calls）→ 程序执行 → 结果以 ToolMessage 回传 → 模型基于结果继续。这是 Agent 能力的根基。

**10. bind_tools 做了什么？**【必背】
把工具的 JSON Schema 附加给 LLM，让模型"看见"有哪些工具、参数怎么填。不加 bind，模型根本不知道有工具。

**11. 工具 docstring 为什么重要？**【必背】
docstring 就是工具的说明书——模型根据它决定何时调用、填什么参数。写得模糊，模型就不会用或乱用。

**12. 多工具并行调用可能出什么问题？你怎么解决的？**【必背，你踩过】
DeepSeek 一次构造多组参数偶发传错。解决：system 约束一次只调一个；工具异常以 ToolMessage 回传让模型自纠；最大轮数防死循环。

**13. 什么是 Agent？LangGraph 里 Agent 的循环怎么实现的？**【必背】
Agent = 模型 + 工具 + 循环。LangGraph：agent 节点调用模型 → 条件路由看有无 tool_calls → 有则进 tools 节点再回 agent → 无则 END。循环由"tools → agent 的边"实现。

## D 组 · RAG

**14. 什么是 RAG？为什么用它？**【必背】
检索增强生成：先从知识库检索相关资料，再把资料拼进 prompt 让模型回答。解决：模型不知道私有/最新知识、减少幻觉、可溯源。

**15. Agentic RAG 和普通 RAG 区别？（项目核心亮点）**【必背】
普通 RAG 是固定管道"先检索后回答"；Agentic RAG 把检索做成工具，模型**自主决定**何时检索、检索几次、要不要组合工具。更灵活，闲聊不浪费检索。

**16. embedding 是什么？为什么用向量检索？**【必背】
把文本映射成向量（我的 bge-small-zh 是 512 维），语义相近的文本向量距离近。向量检索按语义相似度找资料，比关键词匹配更准（"年假怎么请"能匹配"请假制度"）。

**17. chunk 大小怎么选？overlap 是干嘛的？**【必背】
按内容粒度：我选 300 字 + 60 重叠。太大语义稀释、太小上下文断裂；overlap 让切分边界的信息不丢失。答案在 chunk 里，参数影响检索质量。

**18. 检索不到/问题在知识库外怎么办？**【必背】
明确拒绝："文档中未找到相关内容"，绝不编造。我的测试用例"佛山天气"验证了这点。

**19. 向量库用什么？为什么？**【加分】
ChromaDB：轻量、本地文件、和 LangChain 集成好。生产可用 Qdrant/Milvus/Weaviate，支持分布式和过滤。

## E 组 · 记忆

**20. 对话记忆有哪几种实现？你的项目用了哪种？**【必背】
① 消息拼接（简单但爆上下文）② 摘要记忆 ③ 向量记忆（长期）④ **checkpoint 状态持久化**（我的方案）。LangGraph 的 SqliteSaver 存的是**图状态**，不只是消息。

**21. thread_id 是什么？怎么隔离多用户？**【必背】
会话 ID，相当于记忆抽屉。同 ID 共享记忆、不同 ID 互不串味。多用户部署时每个用户一个 thread_id 即可隔离。我验证过：user_01 记得、user_021 不记得。

**22. checkpoint 和"把消息存进数据库"有什么区别？**【加分】
存消息只能恢复消息列表；checkpoint 存**每一步图的完整状态**，支持断点续跑、人工介入、任意时刻快照。

## F 组 · LangGraph 专项

**23. State 是什么？add_messages 干了什么？**【必背】
State 是图共享的状态字典。`Annotated[list, add_messages]` 声明 messages 是**追加语义**（新消息合并进列表），不加它消息会互相覆盖（Day5 思考题①）。

**24. 节点、边、条件路由？**【必背】
节点 = 一段逻辑（agent/tools）；边 = 固定流转（add_edge）；条件路由 = 根据状态决定走哪条（add_conditional_edges）。我的 should_continue 看最后一条消息有没有 tool_calls。

**25. 你的项目图完整讲一遍？**【必背】
START → agent（模型思考）→ should_continue：有 tool_calls → tools 执行（retrieve/subscription_cost/check_api_error）→ 回 agent；无 tool_calls → END。加 SqliteSaver checkpoint 支持多轮记忆。

**26. ToolNode 是什么？**【必背】
LangGraph 内置节点，负责执行工具并把结果包装成 ToolMessage 追加进状态，省得手写 for 循环（对比 Day3 手写版）。

## G 组 · 项目深挖（开放性）

**27. 为什么选 LangGraph 不手写 while 循环？**【必背】
显式图结构可观测、可测试；天然支持 checkpoint/断点/人工介入；条件路由清晰；是生产级标准（面试岗位要求"主流框架"）。

**28. 项目里最难的问题？怎么解决的？**【必背】
多工具调用不稳定（前面讲过）＋环境坑（BGE 版本、HF 离线、SqliteSaver 路径）。话术：定位→验证（独立脚本复现）→修复→沉淀为经验。

**29. 知识库更新了怎么办？**【必背】
重新跑 build_index.py 重建向量库即可。生产上可做增量更新 + 版本管理。

**30. 如果继续做，你会加什么功能？**【加分】
① Rerank 精排提升检索准确率 ② 回答标注引用来源（溯源）③ 多轮查询改写（把"它多少钱"改写成完整问题）④ 流式输出 ⑤ Gradio/Web 界面。选 2 个讲出实现思路即可。

## 面试官"杀招"应对

- **"你项目是不是假的？"** → 如实说"产品是虚构的，但技术栈、架构、踩坑都是真实的，我可以现场演示代码和运行结果"（你的项目真能跑，这是最大底气）
- **"你的模型是 DeepSeek，换成 GPT-4 会不会崩？"** → 兼容 OpenAI 协议，换 base_url 即可；已验证的坑（json_schema）是 DeepSeek 特有，其他模型可能支持，改参数即可
- **"Agent 会不会死循环？"** → 设最大轮数 + 条件路由，超出强制结束（项目里有 MAX_TOOL_ROUNDS 思路）
